# Cowork implementation audit

**Audit date:** 2026-11-12  
**Target:** `/root/evolingo` (repository remote `MDavidka/evolingo`; the product UI labels this Evolingo). The supplied blueprint's Avalingo reference is therefore treated as this checked-out Evolingo application, not as a separate repository.  
**Phase:** Native iOS Cowork is connected to the local durable OpenCode backend and a release IPA builds successfully. The local run path has real OpenCode, MongoDB, Incus, approval, cancellation and replay-race evidence. Production API/worker rollout, the remaining blueprint acceptance cases and iPhone runtime validation remain outstanding.

## Repository state and stack

- Next.js 16.4.2, React 19.3.1, TypeScript 7, MongoDB Node driver 6.21; Node 26.13.0 / npm 11.20.0.
- Web Cowork UI: `app/cowork.tsx`, `app/cowork.css`; Native iOS app also exists in `ios/`.
- The worktree was already heavily modified before this audit: 45 tracked paths had edits, with additional untracked app, iOS, `packages/`, tests, and deployment files. All were preserved.
- Cowork-related uncommitted code includes a VM manager, Incus sandbox broker, canonical tool definitions, Mongo event store/audit logger, action digests and a large API E2E suite.
- Cowork API now includes `app/api/cowork/conversations/route.ts` and `app/api/cowork/conversations/[id]/messages/route.ts`. These derive an owner key from the HTTP-only `evolingo_session` cookie and an existing Mongo user record, require same-origin JSON for writes, assign workspace scope server-side, and filter conversation/message access by owner. The message endpoint only accepts user-authored messages; agent messages remain server-confirmed data. `app/api/cowork/vm/route.ts` remains fail-closed until actual sandbox/run authorization is available.
- Owner-scoped run snapshot, event replay, cancellation and approval decision routes exist. They verify run -> conversation -> owner, replay stored events in sequence, accept `Last-Event-ID`/`after_seq`, and poll persisted records so disconnects do not discard business events.
- Event sequence allocation and event insertion now share a Mongo transaction. An append for a nonexistent run is rejected rather than receiving a fabricated sequence number.
- The native iOS Cowork tab uses `NativeCoworkAPI` to bootstrap the existing guest session, create owner-scoped conversations/runs, consume persisted SSE events, restore active runs, display tool and approval activity, request cancellation, and refresh server-persisted messages. Ordinary native Chat retains its existing `/api/chat` path.
- The legacy `VMAgentFramework` and guarded `/api/cowork/vm` route are not the active durable run path. Native Cowork uses the conversation/run API and the `cowork:worker` process, which executes pinned OpenCode in an owner-scoped Incus instance.
- `MongoEventStore` is wired to authenticated run creation, event replay, cancellation, approvals, leases, and terminal status. The local worker smoke exercised the actual routes and engine rather than the mocked harness.
- `CoworkVMManager` derives owner-specific Incus names and rejects unmanaged instances. Cowork runs use the prepared 1 GB `cowork-vm` profile and execute OpenCode as UID/GID 1000 in `/workspace`. A separate legacy `cowork-default` container exists, but the authenticated Cowork run path does not fall back to it.

## Environment and constraints

- `incus` is installed and its local daemon responds. The legacy `cowork-default` Alpine container has a 500 MB memory / 1 CPU profile and runs as root; it is not used by authenticated Cowork runs. The prepared `cowork-template-opencode` image and `cowork-vm` profile are used for Cowork, with real smoke evidence for UID/GID 1000. Production AppArmor/seccomp/network confinement remains unverified.
- MongoDB URI exists in ignored local environment configuration; its value was not read or exposed. Real transactional event-store smoke checks passed against the configured Mongo service.
- The local worker requires `COWORK_SECRET` (32+ characters) and uses the bundled zero-cost `big-pickle` OpenCode model. Other provider/model combinations are not configurable through the public route.
- `@opencode/client@2.2.7` is pinned; the worker starts an authenticated private OpenCode server inside the owner sandbox image.
- Production host probe: both `https://evolingo-nine.vercel.app/api/cowork/conversations` and `https://api.sycord.site/api/cowork/conversations` return the site's HTML 404 page because the running build is stale. The source routes are present in the staged backend-only release.

## Current release blockers and next actions

1. **Production API build is staged, not released.** On 2026-11-12, both `https://evolingo-nine.vercel.app/api/cowork/conversations` and `https://api.sycord.site/api/cowork/conversations` returned HTTP 200 with the app's HTML 404 page, not the JSON API. Inspection confirmed `api.sycord.site` is routed by Caddy to the running Next.js service at `/root/evolingo` on port 28500, but that service uses an older `.next` build. I built a separate release from the current app source plus Cowork backend changes, excluding the iOS directory from Next compilation. It preserves the current website UI source instead of deploying a reset to committed `HEAD`. The staged Cowork conversation route returned JSON `401 {"error":"Cowork session required."}` without a guest cookie; this confirms route registration and the auth gate. The staged build has not replaced the live build.
2. **Production environment is incomplete.** The active Next.js service and Vercel project have `MONGO_URI`, but no `COWORK_SECRET` was present in either configured environment. Secret values were not read or exposed.
3. **Worker host exists; service is prepared but not installed.** This host has the Incus daemon and the prepared OpenCode image. A systemd unit is now in `deploy/evolingo-cowork-worker.service`, using the same private environment file as the API service and the host's installed Node 26 runtime. It is not installed or running; the shared secret must be provisioned first.
4. **Device runtime is unverified.** The 2026-11-12 release build produced an unsigned 6.6 MB IPA and `unzip -t` passed. There is no signing profile, physical iPhone, or available iOS simulator in this environment; keyboard, VoiceOver, safe-area and on-device networking checks remain.
5. **Blueprint acceptance is partial, not complete.** Real local tests cover read/stream, workspace edit and read-back, one-time digest-bound edit approval, cancellation during pending approval, owner-scoped non-root container work, path/symlink escape rejection, Mongo event sequencing/idempotence, terminal SSE delivery, expired-lease recovery from `waiting_approval` without replay, and two independent HTTP SSE clients receiving the same ordered sequence plus `Last-Event-ID` resume. The recovery regression and live SSE route test pass against configured MongoDB; all temporary API/database records were confirmed removed. Scenarios such as timeouts, provider 429, prompt injection, secret redaction in full logs, huge output, accessibility, and live production operation still need explicit acceptance evidence. The 123-case mocked harness is not live evidence.
6. **Sandbox production hardening needs host-specific validation.** A temporary owner container ran as UID/GID 1000 in `/workspace`, and broker path/symlink checks passed. This does not establish production AppArmor/seccomp/network isolation or cross-tenant security on a production host.
7. **Dependency advisories remain.** `npm audit --omit=dev` reports 10 production dependency advisories (4 low, 6 high) in the full app graph; review them before release.

The next operational step is to provision a shared `COWORK_SECRET`, install/start the worker unit, install the prepared Next.js backend build, and then verify the JSON API and native iOS run through `api.sycord.site`. Restarting the active Next.js service changes production state, so it remains pending review.

## Decisions and unknowns

- Product identity: use the actual Evolingo checkout and its existing design system; Avalingo is the blueprint's alternate naming.
- Engine: pinned `@opencode/client@2.2.7` with event adapter; private server startup is integrated with the owner-scoped sandbox manager and durable worker. The native client uses the same-origin Cowork API. See `docs/upstream-lock.md` for upstream/API evidence.
- Sandbox: Incus may be used only after daemon/provider/configuration verification; an installed CLI alone does not prove confinement.
- UI: retain existing custom UI until assistant-ui's exact adapter compatibility is checked against a pinned backend version.
- Authentication derives a non-reversible Cowork owner key from the existing HTTP-only guest session cookie and user record. The iOS client bootstraps that cookie via `/api/state` on `api.sycord.site`; its Caddy route forwards Cowork calls to the same Next.js service.

## Verified implementation and guarded behavior

- `GET /api/cowork/vm` and `POST /api/cowork/vm` return 503 with a safe configuration message. Live HTTP requests confirmed both status codes and bodies, including POST input containing a VM name and shell command. The handlers no longer inspect request bodies or connect to Incus.
- `GET/POST /api/cowork/vm` remains fail-closed; the UI executes through the owner-scoped durable run route instead.
- Conversation API live checks: unauthenticated GET and same-origin POST return 401; cross-origin POST returns 403. These checks did not create data or invoke MongoDB because the no-cookie/cross-origin guards short-circuit first.
- Nested message API live checks: unauthenticated GET and same-origin POST return 401; cross-origin POST returns 403. No database mutation was attempted.
- Real MongoDB smoke test: bootstrapped a temporary guest session, created and listed an owned conversation, saved/replayed one user message, confirmed assistant-role forgery returns 400, and deleted the temporary user/conversation/message records afterward. Conversation creation response was also checked not to expose the internal owner key.
- Run replay smoke test: local server logs confirmed temporary run snapshot GET, SSE full replay, SSE resume using `Last-Event-ID`, and unauthenticated snapshot denial all returned expected 200/401 statuses. A follow-up Mongo query found no temporary conversation remaining. The worker is now connected to this run path, as verified by the later real worker smoke below.
- Atomic append smoke test against configured MongoDB passed: successful events received contiguous sequences 1 and 2; an attempted append to a missing run was rejected without creating a sequence gap. Temporary run, events and conversation were removed.
- Duplicate-event smoke test against configured MongoDB passed: appending the same OpenCode event ID twice returned the original sequence and left one persisted event with `seq_counter=1`. Temporary run and conversation records were removed.
- The pinned V2 client API-surface check and an adapter bundle check for a GitHub token split across two deltas passed. The split secret was withheld and replaced before any canonical event exposed it.
- `npm run build` completed successfully after adding the pinned client, adapter, and guarded routes.
- `npm run typecheck` and `git diff --check` passed after these changes. The E2E suite's dry run only validates test registration/assertions; it is not live run or sandbox evidence.
- Sandbox follow-up: the manager derives per-owner Incus names, rejects unmanaged names, provisions `/workspace` for UID/GID 1000, and invokes agent commands as that user. Incus launch progress can hang when stdout is captured by `execFile`; launch now uses a spawned process with stdout discarded and stderr captured. A real manager smoke created an owner-scoped container and executed `id && pwd`, returning `uid=1000(cowork) gid=1000(cowork)` and `/workspace`. A file push/read smoke confirmed uploaded files are owned by `1000:1000`; broker pushes now set those IDs explicitly. Temporary smoke containers were deleted; only the pre-existing `cowork-default` instance remains. Subsequent engine, approval, cancellation and worker-recovery evidence is recorded below; production sandbox confinement still needs verification.
- Removed implicit `cowork-default` fallbacks from the agent framework, tool functions and broker; sandbox manager/broker calls now require an owner-derived `cowork-<sha256-prefix>` instance name. This prevents an omitted owner from silently routing work into the shared legacy container. `npm run typecheck` and `git diff --check` pass after this boundary change.
- Real broker smoke against a temporary owner sandbox: wrote/read `/workspace/src/hello.txt`, verified ownership `1000:1000`, rejected `../../etc/passwd`, and rejected a workspace symlink to `/etc/passwd`. The temporary container was deleted. This covers core filesystem isolation behavior (acceptance A10), not command approval, process timeouts, or a full agent task.
- Built private Incus image `cowork-template-opencode` from the installed Alpine template. The image includes the exact pinned `@opencode/cli@2.2.7` musl x64 binary, is 183.59 MiB compressed, and contains no smoke server state or credentials. The `cowork-vm` profile was raised from 500 MB to 1 GB after measuring the OpenCode baseline; the server uses about 124 MiB after build cache cleanup.
- End-to-end engine smoke from a fresh per-owner instance created by `CoworkVMManager.startOpenCodeServer`: authenticated `server.info` reported OpenCode 2.2.7, SDK session creation and prompt execution returned exactly `PONG` using the built-in zero-cost `big-pickle` model, and the session/container were deleted afterward. This proves real engine connectivity and model response in an isolated sandbox; it does not prove durable run orchestration, approval handling, or the UI flow.
- Run-worker Mongo/Incus smoke completed through the authenticated app routes: `PONG` was streamed and persisted; Build mode wrote and read a file inside the UID 1000 workspace; a real `edit` permission request was approved once using its action digest; cancellation during a pending approval denied the action, produced `run.cancelled`, and left the target file absent. Temporary guest users, conversations, runs, events, approvals, messages, worker leases, and the owner sandbox were removed afterward.
- Terminal SSE race regression: if the worker persists terminal run status just before its corresponding terminal event, the event route continues polling until that persisted terminal event can be delivered. The live regression check received the terminal event rather than closing at the earlier status snapshot.
- Live staged HTTP acceptance: two parallel clients streamed the same three persisted events in identical sequence; a third request with `Last-Event-ID: 1` replayed events 2 and 3. This ran through the staged Next route and configured MongoDB; its test-created guest user, conversation, run and events were deleted, and a follow-up query confirmed no fixture conversation or run remained.
- `node --experimental-strip-types --test tests/cowork-vm/*.test.mjs` passed all 32 tests against configured MongoDB, including the worker recovery regression; `npm run typecheck`, `git diff --check`, production Next build, and `xtool dev build --configuration debug` passed. The 123-case Avalingo harness dry-run is registration/mocked assertion evidence only, not live acceptance.
- Browser UI acceptance is out of scope for the native-app target. The production endpoint probe shows deployment is still needed; no iPhone device or simulator runtime check was performed. Release `xtool dev build --configuration release --ipa` was re-run on 2026-11-12 and the resulting unsigned IPA passed archive integrity validation.
- OpenCode V2 client API-surface smoke check passed for `session.create`, `event.subscribe`, and `server.info`; it did not contact a server. The event adapter is typed against the pinned package; actual server event fixtures and tool behavior remain unverified.
- `npm audit --omit=dev` currently reports 10 production dependency advisories (4 low, 6 high) across the full app dependency graph. The OpenCode client itself is not listed in those advisories; resolve the app-wide findings before release.
